# 情绪根源—事实—请求—修复

## R — 原文（Reading）

> “第一，你生气的理由到底是什么；第二，我怎么做你才能够不生气。”

## I — 方法论骨架（Interpretation）

很多对抗不是没有需要，而是当事人对需要感到羞耻、害怕暴露软肋，最后只能用指责保护自己。先还原触发事实，再命名事实勾起的恐惧、委屈或需要，把‘你不爱我’改成对方能够理解和选择的具体请求。激活状态下先恢复到可交流水平，行为责任、规则和补偿随后再谈。表达完成后不靠猜测验收，而看对方能否理解、协商和持续行动。

## A1 — 资料中的应用（Past Application）

### 首次见家长没收到红包引发五天错位争吵

- **问题**：案例中的当事人真正担心不被重视和没有结婚未来，却因羞于说明，连续从回消息等细节挑刺。
- **方法论的使用**：讲者把表面争吵还原为见家长后的具体触发、未来恐惧和希望伴侣回应的需要。
- **结论**：不说真实根源，对方只能把爆发理解为不可理喻。
- **结果**：这是讲者用于解释对抗性机制的假设案例，未提供真实执行结果。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 Skill？

- 已知因为哪件事不舒服，却连续从别的细节挑刺
- 只会说‘你不爱我’，说不出怎样做才算回应
- 双方都很激动，需要先处理状态、后谈规则和责任

### 语言信号

- “我也不知道为什么这么生气，就是觉得他不重视我”
- “我要怎么说，才不是又一次吵架”
- “我希望他懂我，但具体让他做什么我说不清”

### 与相邻 Skill 的区分

- 与 `emotion-root-anxiety-triage` 的区别：连触发点或真正怕什么都不清楚时先用后者；已经知道是哪件事触发、正在错位找茬并准备对外沟通时用本模块，即使情绪词还没有完全命名。
- 与 `resentment-hidden-contract` 的区别：后者逐笔还原长期付出和隐性交换；本模块处理一次具体冲突的表达与修复。

## E — 可执行步骤（Execution）

1. **还原触发事实**
   - 动作：写出第三方可核对的事件，暂时删除‘不爱、故意、从来’等判断。
   - 完成标准：得到一句只描述行为和时间的事实。
2. **命名根源和需要**
   - 动作：说明这件事勾起的恐惧、羞耻、委屈，以及真正希望保护的需要。
   - 完成标准：能回答‘我真正怕什么、要什么’。
3. **选择可承接时机**
   - 动作：确认双方是否已回到能听完一句话的状态。
   - 完成标准：双方没有继续辱骂、威胁或失控。
   - 判停条件：若存在暴力、威胁或明确拒绝沟通，停止修复并优先安全和边界。
4. **提出具体请求并观察**
   - 动作：用事实、自己的感受和一项可选择的具体请求表达，再观察回应和持续行为。
   - 完成标准：请求可执行，且后续有行为证据。

## B — 边界（Boundary）

### 不要在以下情况使用

- 明确违约、侵权或暴力不能被降格为沟通技巧问题。
- 不要用‘表达需要’包装对他人生活的全面控制。

### 语料中明确出现的失败模式

- 不梳理情绪根源而靠细节挑刺。
- 先装懂事积累委屈，再一次性翻全部旧账。
- 在对方无法承接时继续教育和定性。

### 来源局限

- 课程有时把沟通和关系谈判混用；执行时必须保留对方拒绝和协商的权利。
- 清楚表达只能提供修复机会，不能保证对方愿意回应。
